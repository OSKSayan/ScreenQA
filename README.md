# ScreenQA — разбор учебных вопросов по выделенной области экрана

Приложение для Windows 10/11 (C# / .NET 8 / WPF). Живёт в области уведомлений.

1. Нажимаете горячую клавишу (по умолчанию **Q**).
2. Экран затемняется, курсор становится крестиком — выделяете прямоугольник с вопросом (как в Win+Shift+S).
3. Затемнение сразу закрывается, текст распознаётся **локально** движком Windows OCR,
   затем отправляется выбранному ИИ-провайдеру.
4. В небольшом окне рядом с выделением появляются: вопрос, ответ и краткое объяснение.
   Распознанный текст можно поправить и нажать «Спросить ещё раз».

### Быстрая настройка на новом компьютере

Выберите **один** способ подключить Claude:

* **Ключ API (быстрее всего, ~30 секунд).** Запустите `ScreenQA.exe` → двойной щелчок по значку Q у часов
  → «ИИ-провайдер»: «Anthropic Claude — по ключу API» → вставьте ключ → «Сохранить».
  Оплата за запросы с баланса на console.anthropic.com.
* **Подписка Claude Pro/Max через Claude Code (~2–3 минуты).** Установите Claude Code
  (claude.com/claude-code; для Windows обычно `irm https://claude.ai/install.ps1 | iex` в PowerShell),
  выполните один раз `claude auth login`, затем запустите `ScreenQA.exe` — этот способ выбран по умолчанию.

Бесплатный чат claude.ai подключить нельзя: у него нет программного доступа.

### ИИ-провайдеры

* **Claude Code — по подписке, без ключа API (по умолчанию).** ScreenQA вызывает установленный
  Claude Code (`claude -p`) и передаёт ему распознанный текст и картинку выделения через стандартный
  ввод — на диск ничего не пишется. Запросы расходуют лимиты вашей подписки Claude (Pro/Max),
  не сохраняются в историю Claude Code, а инструменты Claude Code отключены (он только отвечает).
  Нужно один раз войти в Claude Code из терминала:

  ```bash
  claude auth login
  ```

  Проверить вход: `claude auth status` → `"loggedIn": true`. Модель можно выбрать в настройках
  (`opus`, `sonnet`, `haiku` или пусто — по умолчанию аккаунта).

Остальные провайдеры — внешние сервисы, нужен свой ключ:

* **Anthropic Claude** — через официальный SDK `Anthropic` для .NET. Ключ: <https://console.anthropic.com> → API Keys.
  Модель по умолчанию `claude-opus-5-5` (можно выбрать `claude-sonnet-5-5`, `claude-haiku-5-5` или вписать свою).
  Для `claude-opus-5-5` включён серверный резерв (`server-side-fallback`): если запрос ошибочно отклонит
  классификатор безопасности, его в том же вызове обработает `claude-opus-4-8`.
  Если ключ в настройках не задан, используется переменная окружения `ANTHROPIC_API_KEY`.
* **OpenAI-совместимый** — любой сервис с API Chat Completions: OpenAI (`https://api.openai.com/v1`),
  OpenRouter (`https://openrouter.ai/api/v1`), локальные Ollama (`http://localhost:11434/v1`) или
  LM Studio (`http://localhost:1234/v1`) — для локальных ключ не нужен. Название модели указываете сами.

OCR не требует ключа и интернета: используется встроенный `Windows.Media.Ocr`.

## Сборка и запуск

```bash
dotnet build ScreenQA/ScreenQA.csproj -c Release
```

```bash
dotnet run --project ScreenQA/ScreenQA.csproj
```

Готовый exe после сборки: `ScreenQA/bin/Release/net8.0-windows10.0.19041.0/ScreenQA.exe`.

Один файл без установки .NET на целевом ПК:

```bash
dotnet publish ScreenQA/ScreenQA.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o publish
```

Автотесты (шифрование ключей, вырезание секретов из журнала, разбор ответа ИИ, настоящий OCR Windows и т. д.):

```bash
dotnet test ScreenQA.Tests/ScreenQA.Tests.csproj
```

Перед сборкой закройте запущенный ScreenQA (значок в трее → «Выход»): иначе exe будет занят.

### Первый запуск

1. Запустите `ScreenQA.exe` — появится значок «Q» у часов и уведомление.
2. Двойной щелчок по значку → **Настройки**: выберите провайдера, вставьте ключ API, при необходимости
   поменяйте горячую клавишу и язык распознавания → «Сохранить».
3. Нажмите горячую клавишу и выделите вопрос.

Автозапуск: положите ярлык `ScreenQA.exe` в папку `shell:startup` (Win+R → `shell:startup`).

## Настройки

* **Горячие клавиши** — список: выделение запускает любое из сочетаний (например, и `Q`, и `Shift + Q`).
  «+ Добавить сочетание» → щёлкнуть по полю → нажать клавишу или сочетание; «Удалить» убирает строку.
  Одиночная клавиша без модификаторов перехватывается во всех программах (её нельзя будет напечатать,
  пока ScreenQA запущен; в окнах самого ScreenQA можно). Есть пауза в меню значка. Если сочетание
  занято другой программой, настройки не сохранятся и покажут, какое именно.
* Запуск `ScreenQA.exe --settings` сразу открывает настройки (удобно для ярлыка).
* **Язык распознавания** — «Автоматически» (языки профиля Windows) или конкретный установленный язык.
* **ИИ-провайдер**, модель, ключ, язык ответа.
* **Отправлять изображение в ИИ** — выключено по умолчанию; включите для формул и схем
  (модель должна поддерживать изображения).
* **Скрывать от записи экрана** — см. ниже.

## Приватность

* **Снимки экрана** делаются только по нажатию горячей клавиши (или «Выделить область» в меню значка),
  чтобы показать «замороженный» экран для выделения. Снимок живёт в памяти, после выделения полные
  снимки мониторов сразу удаляются, а вырезанная область — когда закрываете окно ответа.
  **На диск ничего не пишется**, кроме случая, когда вы сами нажмёте «Сохранить снимок…».
* **Что уходит в сеть**: распознанный текст (и картинка, только если включили это в настройках) —
  выбранному провайдеру. Больше никуда.
* **Ключи API** хранятся в `%AppData%\ScreenQA\settings.json` в зашифрованном виде (Windows DPAPI,
  расшифровать может только ваша учётная запись на этом ПК). В журнал (`%LocalAppData%\ScreenQA\logs`)
  ключи не пишутся: известные ключи и всё, похожее на `sk-…`, `Bearer …`, `x-api-key`, вырезается.
  Распознанный текст и ответы тоже не журналируются — только их длина.

### Скрытие окна от записи и демонстрации экрана

Окно ответа и окно настроек помечаются системной функцией
`SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`. Состояние видно в окне ответа (значок в заголовке)
и в настройках:

| Статус | Что значит |
|---|---|
| 🟢 Скрыто от записи | В записи на месте окна виден фон под ним |
| 🟠 Частично скрыто | Старая Windows: вместо окна чёрный прямоугольник |
| 🔴 Защита не работает | Windows отказала (например, сеанс RDP) |
| ⚪ Видно в записи | Настройка выключена |

**Ограничения:** работает с программами, которые захватывают экран стандартными средствами Windows
(обычно OBS, Teams, Zoom, Discord, «Ножницы», Xbox Game Bar). Не гарантируется для драйверного захвата,
некоторых программ записи, удалённого рабочего стола, внешних карт видеозахвата и, разумеется, съёмки
экрана камерой. Проверьте с вашей программой записи.

Затемнение и рамка выделения по умолчанию тоже скрыты от записи (отдельная галочка в настройках):
в записи видна страница под ними, а курсор в этом режиме остаётся обычной стрелкой, потому что
программы записи рисуют курсор сами. Движение мыши при выделении в записи всё равно видно.

```
ScreenQA/
  ScreenQA.csproj, app.manifest      — проект .NET 8 WPF, Per-Monitor DPI v2
  App.xaml(.cs)                      — трей, горячая клавиша, сценарий выделение → OCR → ИИ
  Native/NativeMethods.cs            — WinAPI: RegisterHotKey, SetWindowDisplayAffinity, DPAPI
  Services/
    HotkeyService.cs                 — глобальная горячая клавиша
    ScreenCaptureService.cs          — снимок мониторов по нажатию клавиши
    OcrService.cs                    — Windows.Media.Ocr
    CaptureProtection.cs             — скрытие окон от записи + статус
    SecretProtector.cs               — шифрование ключей DPAPI
    AppSettings.cs                   — настройки (JSON)
    Log.cs                           — журнал с вырезанием секретов
    TrayIcon.cs, ImageUtil.cs, UserFacingException.cs
    Ai/                              — промпт, Anthropic (SDK), OpenAI-совместимый (HTTP)
  Views/
    SelectionOverlay.xaml            — затемнение и выделение (по окну на монитор)
    AnswerWindow.xaml                — окно ответа
    SettingsWindow.xaml              — настройки
ScreenQA.Tests/                      — автотесты xUnit
```

## Частые проблемы

* **«Не установлено ни одного языка распознавания»** — добавьте язык в Windows (см. таблицу выше)
  и перезапустите ScreenQA.
* **Горячая клавиша не срабатывает** — сочетание занято другой программой; выберите другое в настройках.
  Q без модификаторов не срабатывает, пока вы печатаете в окне ScreenQA — это сделано специально.
* **401 / неверный ключ** — проверьте ключ в настройках; «Удалить ключ» и вставьте заново.
* Подробности ошибок — меню значка → «Открыть папку журнала».
